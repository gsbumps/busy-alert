# התראת עומס מגוגל מפות במייל

המערכת רצה בחינם על השרתים של GitHub כל 30 דקות. היא פותחת כל מקום בגוגל מפות, קוראת את מדד העומס החי ("Currently X% busy, usually Y% busy") ושולחת לך מייל כשהמקום נהיה עמוס ובכל פעם שמצב העומס משתנה. המחשב שלך לא צריך להיות דלוק.

## שלב 1: סיסמת אפליקציה ב-Gmail (3 דקות)
המערכת שולחת את המייל מחשבון ה-Gmail שלך אל עצמך. גוגל לא מאפשרים להשתמש בסיסמה הרגילה, לכן יוצרים סיסמה מיוחדת:
1. ודא שהאימות הדו-שלבי מופעל בחשבון: myaccount.google.com/security → "אימות דו-שלבי".
2. היכנס ל-**myaccount.google.com/apppasswords**.
3. תן שם (למשל "busy alert") ולחץ **צור**.
4. תקבל סיסמה של 16 אותיות. העתק ושמור אותה — היא מוצגת פעם אחת בלבד.

> אם הדף לא נפתח: בחשבונות עבודה/ארגון לפעמים המנהל חוסם סיסמאות אפליקציה. אפשר להשתמש בחשבון Gmail פרטי כשולח ולשלוח לכל כתובת שתרצה (ראה `EMAIL_TO` למטה).

## שלב 2: מאגר ב-GitHub
1. היכנס ל-github.com (או פתח חשבון חינמי) ולחץ **New repository**.
   - מאגר **Public**: דקות הרצה ללא הגבלה. התוכן (שמות המקומות) גלוי, הסיסמה נשמרת כסוד ולא גלויה.
   - מאגר **Private**: 2,000 דקות בחודש בחינם — מספיק לבדיקה כל 30 דקות במקום אחד או שניים.
2. במאגר החדש: **Add file → Upload files**, וגרור את `monitor.py`, `config.json`, `requirements.txt`, `README.md`.
3. את קובץ התזמון יוצרים ידנית (תיקיות שמתחילות בנקודה לא תמיד עולות בגרירה):
   **Add file → Create new file**, בשם הקובץ כתוב בדיוק `.github/workflows/busy-alert.yml`, הדבק את התוכן של `busy-alert.yml` ולחץ **Commit**.

## שלב 3: סודות
במאגר: **Settings → Secrets and variables → Actions → New repository secret**, צור:
- `EMAIL_ADDRESS` — כתובת ה-Gmail שלך (השולח)
- `EMAIL_APP_PASSWORD` — הסיסמה משלב 1 (אפשר עם או בלי רווחים)
- `EMAIL_TO` — *לא חובה.* כתובת אחרת לקבלת ההתראות. אם לא תיצור אותו, המייל יגיע לכתובת השולח.

## שלב 4: הגדרת המקומות (`config.json`)
| שדה | משמעות |
|---|---|
| `name` | השם שיופיע בכותרת המייל |
| `url` | קישור למקום מגוגל מפות (שיתוף → העתק קישור) |
| `min_level` | מאיזה מצב לשלוח מייל: `A little busy`, `Busy`, `Busier than usual` או `As busy as it gets` |
| `notify_when_clear` | `false` = בלי מייל כשהעומס יורד מתחת לסף (ברירת מחדל). `true` = שלח גם מייל "🟢 נרגע" |
| `check_hours` | שעות הבדיקה (שעון ישראל). `end` לא כולל |
| `check_days` | ימים: 0=ראשון ... 6=שבת |

אפשר להוסיף כמה מקומות — כל אחד בסוגריים מסולסלים משלו בתוך `places`.

### כותרות המיילים
| מצב בגוגל | כותרת |
|---|---|
| A little busy | 🟡 קצת עמוס \| שם המקום |
| Busy | 🟠 עמוס \| שם המקום |
| Busier than usual | 🔴 עמוס מהרגיל \| שם המקום |
| As busy as it gets | 🟣 עמוס כמו בשיא \| שם המקום |

מייל נשלח כשהמקום נכנס לעומס ובכל פעם שמצב העומס משתנה (למשל מ-🟡 ל-🟠), ולא שוב ושוב על אותו מצב.

## שלב 5: בדיקה
**Actions → Busy alert → Run workflow**. תוך 2–3 דקות יגיע אליך מייל בדיקה עם מצב העומס הנוכחי של כל מקום. מכאן זה רץ לבד.

## טוב לדעת
- נתון חי קיים רק למקומות פופולריים ורק כשהם פתוחים. אם במייל הבדיקה כתוב "אין כרגע נתון חי" — זה תקין כשהמקום סגור.
- אם המייל לא מגיע — בדוק בתיקיית הספאם וסמן "לא ספאם".
- כדי לקבל התראה קופצת בטלפון, ודא שההתראות של אפליקציית Gmail מופעלות.
- GitHub מריץ תזמונים בעיכוב של כמה דקות לפעמים.
- אם גוגל ישנו את עיצוב הדף והמערכת תפסיק לקרוא נתונים, מייל הבדיקה יראה זאת — ואפשר לעדכן את הסקריפט.
- במאגר שלא היה בו שינוי 60 יום GitHub עשוי להשבית את התזמון ולשלוח מייל; לחיצה אחת על **Enable workflow** מחזירה אותו.
